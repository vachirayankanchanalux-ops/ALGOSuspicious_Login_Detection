# Suspicious Login Detection

ตรวจหาบัญชีที่อาจถูกโจมตีแบบ brute force จาก log การล็อกอิน
โดยแจ้งเตือนเมื่อบัญชีเดียวกันล็อกอินล้มเหลว (`FAILED`) ติดต่อกันตั้งแต่ 3 ครั้งขึ้นไปภายใน 5 นาที
(การบ้านครั้งที่ 2 รายวิชา CNC211 Algorithm)

## Requirements
- Python 3.8 ขึ้นไป (ทดสอบแล้วกับ Python 3.13)
- โปรแกรมหลักไม่ใช้ library ภายนอก ใช้แค่ standard library
  - `csv` อ่านไฟล์และแยกแต่ละบรรทัดตามจุลภาค
  - `sys` รับชื่อไฟล์จากบรรทัดคำสั่ง (`sys.argv`)
  - `datetime` (`datetime`, `timedelta`) แปลงข้อความเป็นเวลาและคำนวณช่วง 5 นาที
  - `collections` (`deque`) ใช้เฉพาะใน `SlidingWindow.py`
- ไม่ได้ใช้ `sorted()` หรือ `.sort()` ของ Python อัลกอริทึมเรียงทุกตัวเขียนเองตามสไลด์

## Usage
```bash
python <main.py> login.txt
```
แทน `<main.py>` ด้วยไฟล์ของวิธีที่ต้องการ

```bash
python BruteForce2.py login.txt      # Selection Sort + Sequential Scan
python SequentialScan.py login.txt   # Mergesort + Sequential Scan
python SlidingWindow.py login.txt    # Mergesort + Hash Map + deque
```
- ถ้าไม่ระบุชื่อไฟล์ โปรแกรมจะอ่าน `login.txt` ในโฟลเดอร์เดียวกัน
- บน macOS / Linux บางเครื่องให้ใช้ `python3` แทน `python`

## Input Format
ไฟล์ `login.txt` บรรทัดแรกเป็นหัวตาราง (ถูกข้าม) บรรทัดถัดไปหนึ่งบรรทัดคือหนึ่งเหตุการณ์
ประกอบด้วย 4 ฟิลด์ คั่นด้วยจุลภาค `,`

| ฟิลด์ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `timestamp` | `2026-10-01 09:00:01` | รูปแบบ `%Y-%m-%d %H:%M:%S` แปลงเป็น `datetime` |
| `username` | `alice` | ใช้แยกบัญชี |
| `ip_address` | `192.168.1.10` | อ่านมาแต่ไม่ใช้ในการตัดสิน (ดู Assumptions ข้อ 1) |
| `status` | `SUCCESS` / `FAILED` | มีช่องว่างต่อท้ายในบางบรรทัด |

ตัวอย่างบรรทัดจริง:
```
timestamp,username,ip_address,status
2026-10-01 09:00:01,alice,192.168.1.10,FAILED
2026-10-01 09:25:00,grace,192.168.1.72,SUCCESS
2026-10-01 09:26:00,heidi,192.168.1.80,FAILED
2026-10-01 09:00:15,alice,192.168.1.10,FAILED
```
ข้อมูลทั้งไฟล์มี 29 เหตุการณ์ จาก 8 บัญชี และ**ไม่ได้เรียงตามเวลา** (บรรทัดที่ 2 เป็น 09:25 แต่บรรทัดที่ 3 ย้อนกลับเป็น 09:00)

## Detection Rules
- นับ `FAILED` ที่**ติดต่อกัน**ของบัญชีเดียวกัน หลังเรียงตามเวลาแล้ว
- **แจ้งเตือน** เมื่อมี `FAILED` ≥ 3 ครั้ง และเวลาครั้งสุดท้ายลบครั้งแรก ≤ 5 นาที (300 วินาที)
- **รีเซ็ต** เมื่อพบ `SUCCESS` ของบัญชีนั้น `FAILED` ก่อนหน้าจะไม่ถูกนับรวมกับ `FAILED` หลังจากนั้น
- หากเกิดเงื่อนไขอีกครั้งหลังรีเซ็ต จะนับเป็นการแจ้งเตือนใหม่

วิธีนับเมื่อผิดเกิน 3 ครั้ง ต่างกันตามไฟล์ (โจทย์ไม่ได้กำหนด)

| ไฟล์ | พฤติกรรม | ผิด 6 ครั้งใน 2.5 นาที |
|---|---|---|
| `BruteForce2.py`, `SequentialScan.py` | รวม `FAILED` ทั้งหมดที่อยู่ใน 5 นาทีนับจากครั้งแรกเป็นการแจ้งเตือนเดียว แล้วเริ่มช่วงใหม่จากครั้งถัดไป | 1 การแจ้งเตือน (6 ครั้ง) |
| `SlidingWindow.py` | แจ้งทันทีที่ครบ 3 ครั้ง แล้วล้างหน้าต่างเริ่มนับใหม่ | 2 การแจ้งเตือน (3 + 3) |

## Example Output
```
$ python SequentialScan.py login.txt
ตรวจ 29 รายการจาก login.txt
พบบัญชีน่าสงสัย 2 รายการ

Username    FAILED   ช่วงเวลาที่ตรวจพบ
----------------------------------------------------
david            3   2026-10-01 09:10:00 - 09:11:00
frank            3   2026-10-01 09:22:00 - 09:23:00
```
ผลลัพธ์แต่ละรายการแสดง `username`, จำนวน `FAILED` และเวลาเริ่ม–สิ้นสุด
ทั้ง 3 ไฟล์ได้ผลตรงกัน (`BruteForce2.py` พิมพ์เพิ่ม 1 บรรทัด: `เปรียบเทียบคีย์ 406 ครั้ง (n(n-1)/2 = 406)`)

บัญชีที่ไม่ถูกแจ้งเตือน
- `charlie`, `eve` ผิดครบ 3 ครั้ง แต่ใช้เวลา 5:10 และ 5:01 นาที
- `alice`, `heidi` ถูก `SUCCESS` ตัดก่อนครบ 3 ครั้ง
- `bob`, `grace` ผิดแค่ 2 ครั้ง

## Assumptions
1. **ตรวจต่อบัญชี (username) ไม่ใช่ต่อ IP**
   ผู้โจมตีสามารถสลับ IP ได้ (ในข้อมูลพบ `alice` ใช้ทั้ง `192.168.1.10` และ `.11`, `david` ใช้ `.40` และ `.41`)
   ถ้านับแยกตาม IP จำนวนครั้งจะกระจายจนไม่ถึงเกณฑ์
2. **ขอบเขต 5 นาทีรวมค่าขอบ** (`<= WINDOW`)
   ห่างกันพอดี 5:00 นาทีถือว่าเข้าเงื่อนไข, 5:01 นาทีไม่เข้า
3. **ลดการแจ้งเตือนซ้ำ**
   `BruteForce2.py` และ `SequentialScan.py` รวมการผิดในช่วงเดียวกันเป็นการแจ้งเตือนเดียว
   ส่วน `SlidingWindow.py` เน้นแจ้งให้เร็วที่สุด (ดู Detection Rules)
4. **การแจ้งเตือนคือ "ควรตรวจสอบ"** ไม่ได้ยืนยันว่าถูกโจมตีจริง (ตามใบงาน)

## Preprocessing
- ข้ามบรรทัดหัวตารางและบรรทัดว่าง
- ตัดช่องว่างหัวท้ายของ**ทุกฟิลด์**ด้วย `.strip()` (บางบรรทัดมีช่องว่างต่อท้าย เช่น `"FAILED "`)
  ถ้าไม่ตัด `status == "FAILED"` จะเป็นเท็จทุกครั้งและไม่มีการแจ้งเตือนเลย
- แปลง `timestamp` เป็น `datetime` เพื่อลบหาระยะห่างของเวลาได้
- เก็บเป็น tuple `(username, datetime, ip, status)` โดยให้ชื่อมาก่อนเวลา เพื่อใช้เป็นคีย์เรียงได้ทันที
- **เรียงข้อมูลก่อนตรวจ** เพราะไฟล์ไม่ได้เรียงลำดับ (เช่น `david 09:10:00` อยู่ท้ายไฟล์) ถ้าไม่เรียงจะตรวจจับผิด
  - `BruteForce2.py`, `SequentialScan.py` เรียงตาม `(username, เวลา)` ให้บัญชีเดียวกันอยู่ติดกัน
  - `SlidingWindow.py` เรียงตามเวลาอย่างเดียว เพราะแยกบัญชีด้วย Hash Map แล้ว

## Algorithms
ให้ n = จำนวนบรรทัดใน log และ u = จำนวนบัญชี

| ไฟล์ | ขั้นเรียง | ขั้นตรวจจับ | Time รวม | Space | อ้างอิงสไลด์ |
|---|---|---|---|---|---|
| `BruteForce2.py` | Selection Sort Θ(n²) | Sequential Scan Θ(n) | **Θ(n²)** | O(n) | slide03 สไลด์ 4–7, 13 |
| `SequentialScan.py` | Mergesort Θ(n log n) | Sequential Scan Θ(n) | **Θ(n log n)** | O(n) | slide04 สไลด์ 12–17 |
| `SlidingWindow.py` | Mergesort (เวลา) Θ(n log n) | Hash Map + deque Θ(n) | **Θ(n log n)** | O(n) + O(u) | slide04 (เฉพาะขั้นเรียง) |

- ทุกวิธีมีขั้นตรวจจับเป็นเชิงเส้น เวลาส่วนใหญ่จึงอยู่ที่ขั้นเรียง
- จำนวนการเปรียบเทียบคีย์กับ `login.txt`: Selection Sort = 406 ครั้ง (= 29×28/2), Mergesort = 94 ครั้ง
- ถ้า log เรียงตามเวลามาแล้ว `SlidingWindow.py` ข้ามขั้นเรียงได้ เหลือ Θ(n)
- Hash Map, deque และ Sliding Window เป็นเนื้อหานอกสไลด์ของรายวิชา

ผลวัดเวลา (Log สุ่ม, ค่ากลางจาก 3 รอบ, Python 3 บน Intel Xeon 2.1 GHz):

| n | BruteForce2 | SequentialScan | SlidingWindow |
|---|---|---|---|
| 1,000 | 79.1 ms | 2.2 ms | 1.5 ms |
| 8,000 | 5,159.7 ms | 20.3 ms | 14.1 ms |
| โตขึ้นเมื่อ n × 8 | 65 เท่า (n² ทำนาย 64) | 9.2 เท่า (n log n ทำนาย ≈ 10) | 9.4 เท่า |

## Test Cases
ทดสอบกับทั้ง 3 ไฟล์ ผลตรงกันทุกเคส ยกเว้นเคสสุดท้ายตามที่อธิบายใน Detection Rules

| เคส | ข้อมูล (บัญชีเดียวกัน) | ผลที่คาดหวัง |
|---|---|---|
| FAILED 3 ครั้ง ห่างพอดี 5:00 | F 10:00:00, F 10:02:00, F 10:05:00 | แจ้งเตือน 3 ครั้ง |
| FAILED 3 ครั้ง ห่าง 5:01 | F 10:00:00, F 10:02:00, F 10:05:01 | ไม่แจ้งเตือน |
| FAILED 2 ครั้ง → SUCCESS → FAILED 1 ครั้ง | F 10:00:00, F 10:00:30, S 10:01:00, F 10:01:30 | ไม่แจ้งเตือน (รีเซ็ต) |
| FAILED 3 ครั้งจากคนละ IP | F 10:00:00 (IP 1), F 10:00:30 (IP 2), F 10:01:00 (IP 3) | แจ้งเตือน 3 ครั้ง |
| บรรทัดไม่เรียงเวลา | F 10:01:00, (บัญชีอื่น), F 10:00:00, F 10:00:30 | แจ้งเตือน 3 ครั้ง (ถูกต้องหลังเรียง) |
| FAILED 6 ครั้งใน 2.5 นาที | F ทุก 30 วินาที ตั้งแต่ 10:00:00 | BruteForce2 / SequentialScan: 1 รายการ (6) · SlidingWindow: 2 รายการ (3 + 3) |
| ข้อมูลจริง | `login.txt` | `david` 3 ครั้ง และ `frank` 3 ครั้ง |

## Limitations
- การแจ้งเตือนไม่ได้แปลว่าถูกโจมตีจริง เช่น ผู้ใช้อาจลืมรหัสผ่าน
- ตรวจไม่พบการโจมตีแบบช้า (low-and-slow) ที่เว้นช่วงเกิน 5 นาที
- ตรวจไม่พบ password spraying (ลองรหัสเดียวกับหลายบัญชี) เพราะนับแยกต่อบัญชี
- ผู้โจมตีที่สลับ `SUCCESS` เข้ามาเป็นระยะ (เช่น ล็อกอินบัญชีที่ตนควบคุมได้) ทำให้ตัวนับรีเซ็ตได้
- ต้องอ่าน log ทั้งไฟล์เข้าหน่วยความจำก่อนเรียง ยังไม่รองรับการอ่านแบบ stream
- `BruteForce2.py` ช้ามากเมื่อ log ใหญ่ (8,000 แถวใช้ประมาณ 5 วินาที) เหมาะใช้เป็นคำตอบอ้างอิงเท่านั้น
