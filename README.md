# Suspicious Login Detection

ตรวจหาบัญชีที่อาจถูกโจมตีแบบ brute force จาก log การล็อกอิน
โดยแจ้งเตือนเมื่อบัญชีเดียวกันล็อกอินล้มเหลว (`FAILED`) ตั้งแต่ 3 ครั้งขึ้นไปภายใน 5 นาที

## Requirements
- Python <3.x>
- ไม่ใช้ library ภายนอก (ใช้แค่ standard library: `datetime`, ...)

## Usage
```bash
python <main.py> login.txt
```

## Input Format
ไฟล์ `login.txt` หนึ่งบรรทัดคือหนึ่งเหตุการณ์ ประกอบด้วย 4 ฟิลด์ คั่นด้วย `<,>`

| ฟิลด์ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `timestamp` | `2026-10-01 09:00:01` | แปลงเป็น `datetime` |
| `username` | `alice` | |
| `ip_address` | `192.168.1.10` | |
| `status` | `SUCCESS` / `FAILED` | |

ตัวอย่างบรรทัดจริง:
```
<คัดบรรทัดจริงจาก login.txt มาวาง>
```

## Detection Rules
- **เริ่มแจ้งเตือน** เมื่อบัญชีหนึ่งมี `FAILED` ≥ 3 ครั้ง และเวลาครั้งสุดท้ายลบครั้งแรก ≤ 300 วินาที
- **รวมเข้าการแจ้งเตือนเดิม** หาก `FAILED` ครั้งถัดไปยังเข้าเงื่อนไข (เพิ่มจำนวนครั้งและขยายเวลาสิ้นสุด แทนการแจ้งซ้ำ)
- **การแจ้งเตือนสิ้นสุด (streak รีเซ็ต)** เมื่อพบ `SUCCESS` หรือเมื่อ `FAILED` ภายใน 5 นาทีล่าสุดเหลือน้อยกว่า 3 ครั้ง
- หากเกิดเงื่อนไขอีกครั้งหลังรีเซ็ต จะนับเป็นการแจ้งเตือนใหม่

## Example Output
```
<วางผลลัพธ์จริงจากการรันกับ login.txt>
```
ผลลัพธ์แต่ละรายการแสดง: `username`, จำนวน `FAILED`, เวลาเริ่ม–สิ้นสุด

## Assumptions
1. **ตรวจต่อบัญชี (username) ไม่ใช่ต่อ IP**
   ผู้โจมตีสามารถสลับ IP ได้ (ในข้อมูลพบ `alice` ใช้ทั้ง `192.168.1.10` และ `.11`)
   ถ้านับแยกตาม IP จำนวนครั้งจะกระจายจนไม่ถึงเกณฑ์
2. **ขอบเขต 5 นาทีรวมค่าขอบ**
   ห่างกันพอดี 5:00 นาทีถือว่าเข้าเงื่อนไข, 5:01 นาทีไม่เข้า
3. **แจ้งเตือน 1 ครั้งต่อการโจมตีหนึ่งช่วง (burst)**
   เพื่อไม่ให้ผู้ดูแลได้รับแจ้งเตือนซ้ำ ๆ จากการโจมตีครั้งเดียวกัน

## Preprocessing
- ตัดช่องว่างหัวท้ายของ**ทุกฟิลด์**ด้วย `.strip()` (บางบรรทัดมีช่องว่างต่อท้าย เช่น `"FAILED "`)
- แปลง `timestamp` เป็น `datetime` เพื่อคำนวณระยะห่างของเวลา
- **เรียงเหตุการณ์ของแต่ละบัญชีตามเวลา** เพราะไฟล์ไม่ได้เรียงลำดับ
  (เช่น `david 09:10:00` อยู่ท้ายไฟล์) ถ้าไม่เรียงจะตรวจจับผิด

## Algorithms
ให้ n = จำนวนบรรทัดใน log

| ขั้นตอน | วิธี | Time | Space |
|---|---|---|---|
| เรียงตามเวลา | Merge sort | O(n log n) | O(n) |
| ตรวจจับ | Brute force | O(n²) | O(1) |
| ตรวจจับ | Sliding window | O(n) | O(n) |

รวมทั้งระบบเมื่อใช้ sliding window: **O(n log n)** (เวลาส่วนใหญ่อยู่ที่การเรียง)

## Test Cases
| เคส | ข้อมูล | ผลที่คาดหวัง |
|---|---|---|
| FAILED 3 ครั้ง ห่างพอดี 5:00 | ... | แจ้งเตือน |

| บรรทัดไม่เรียงเวลา | ... | ตรวจจับถูกต้องหลังเรียง |

## Limitations
- การแจ้งเตือนไม่ได้แปลว่าถูกโจมตีจริง เช่น ผู้ใช้อาจลืมรหัสผ่าน
- ตรวจไม่พบการโจมตีแบบช้า (low-and-slow) ที่เว้นช่วงเกิน 5 นาที
- ตรวจไม่พบ password spraying (ลองรหัสเดียวกับหลายบัญชี) เพราะนับแยกต่อบัญชี
